# 週ボス共通：文脈操作・入力由来・共有予約の契約 v0.1

2026-11-17。デザインと独立参照モデルの契約であり、Lua／実機ネットワークの実装ではない。目的はS-05の誤違反と所有者喪失による予約残留を防ぐこと。既存J保持・E交代・Q光界・マクロ・主人公60技を変更しない。

## 操作の種類を分ける

| mode | 例 | 資源・時間・所有 |
|---|---|---|
| press | 試練の確認・場面への同意 | 一入力一結果。重複requestを無視 |
| hold_personal | WK08返済灯 | actor世代別。共有予約を取らない。45tick開始/30tick周期 |
| hold_shared | WT20霜印 | 指定対象へ90tick操作。共有CD120tick、完了後は予約を持たない |
| aim_shared | WN14照準端末 | C100を予約し、実発射で消費。空振り返金なし |
| command_normal | WK09償還の一撃 | 既存通常を要求。既存CT/lock/射程に従う。必中・無料キャンセルなし |

物理キーは入力マップへ別途割当て、ここでは奪わない。画面の文脈ボタンはactionId/targetId/mode/必要時間/残資源/取消理由を表示。必須操作が未対応なら見た目だけ作って「攻略可能」と記録しない。

## 入力イベントの必須情報

`trialId, sceneEpoch, realPlayerId, actorId, actorGeneration, requestId, actionId, targetId, origin, acceptedTick, rootCastId, rootStartedTick, logicalFacing, rootMoves`を扱う。不要なフィールドは作用種別で明示する。ネットワーク再送と一連の多段hitは別のID。

originはmanual/manual_repeat/ai/forced/sync/auto_aim/animationを区別する。manual_repeatはJ保持で新しく発動した一回の攻撃。AIの自動スキル、以前のcastの子ヒット、髪や呼吸の描画をmanual_repeatへ混ぜない。位置差そのものは由来の代用にならない。

## WM09 停止とWM10 直視

元の準備[0,120)、判定[120,420)は維持する。

停止は判定期間に受理された新規manual/manual_repeatの能動移動・回避・ジャンプ、または期間開始以後に始まったroot移動攻撃を対象にする。準備前や準備中に始まった旧rootの残移動、強制移動、同期、AI、表示offsetは対象外。判定開始前に着地と残ロック終了を確認し、準備中に移動を伴うJ連撃を止めるよう示す。

直視はカメラや画像ミラーではなく論理facing。自動照準補正でプレイヤーを誤違反にしない。手動で向きを指定した新規攻撃の向きは判定する。期間終了の時刻420は期間外。交代自体は罰せず、既に成立した違反はrealPlayerIdへ保持する。一禁令一人一違反。

由来やroot開始時刻が欠落・不明なら、`unsupported_provenance`を出して**その条件で罰を発生させない**。これを正常な完成状態にしない。実装側のイベント提供を先に接続する。今回の自動テストは主に停止の参照判定15種で、実際の視線制御・AI・入力配信を検証していない。

## 共有予約のライフサイクル

`IDLE → RESERVED → COMMITTED / CANCELLED / EXPIRED`。各予約tokenはresourceId、trial、scene、serial、owner(realPlayer+actorGeneration)、target、取得tickを持つ。開始には所有者が生存・操作中・範囲内・対象有効・資源十分であることが必要。

- 予約時にCは減らさない。表示上は他人が使えない予約済み状態とする。
- 実発射でtokenと全条件を再検証し、C100を一度だけ減らす。弾が外れても戻さない。commitの再送は二重消費にならない。
- 発射前の死亡、切断、交代、範囲外、被弾割込み、対象失効、勝利/全滅、sceneEpoch変更、明示取消は予約を解放する。予約だけなので**返金は0**。
- 古いtokenのcommit/release/renewは新しい所有者の予約へ作用させない。対象消滅後の予約が次の同名装置へ引き継がれないようtargetGenerationも扱う。
- shared照準のleaseは120tick。保持と有効性を確認する更新は30tick以内を目標とする。更新しても取得から300tickを越えて独占しない。期限は半開、終了tickで復活させるrenewは拒否。
- 期限切れ後の同じ押し続け入力だけで即座に自動再予約しない。離して押す新入力、または順序付きの待ち要求へ機会を渡す。実FIFO/公平性と回線遅延は別検証。
- WK08の個人保持はこの共有leaseを使わない。最大契約5.25秒の返済を、5秒の共有照準上限で切ってはいけない。場面同意の待ち状態もCを予約しない。

同tickの勝利/終了・owner喪失を先に処理し、その後に有効commitを一度だけ認める。期限tickのcommitは拒否する。観測順序で死んだ人が撃てたり、切断した人が永久に独占したりしない。

## キャンセル後の保持と例外

個人返済は完了済みの減少を戻さず、未完了の保持だけ捨てる。交代して別actorがDを引き継いだり、旧actorの返済時計をリセットしてFを複製したりしない。保持中のHP更新をすべて同じ割込みへ流す実装では、DoTと行動割込み付き被弾の区分を先に提供する。

花・柱・核の有効hit回数はcast/event/targetの明示した重複抑制を使う。射線のVFX、物体cleanup、支援対象の消去を攻撃成功や雑魚報酬へ変換しない。hit受付の閉じた時刻に新しいhitを足さない。既に期間内で成立した成功と期限通知の競合では成功を維持する。

## 必須の統合テスト（未実施）

通常単独→同行停止→同行稼働→人間2/4人の順で接続する。保持Jと文脈操作の競合、owner交代/死亡/通信切断、旧cast残移動、ターゲット再生成、場面切替直後の再送、期限境界、同tick消費/喪失をイベントログで確認する。`requestId, token, origin, accepted/rejected, reason`を記録し、個人の秘密情報や実セーブは登録しない。
