## 2. 索引と本文の関係・例外

`source_of_truth`の二文書を姿勢・幾何・条件の詳細基準にする。MANIFESTは設計索引で、既存ランタイムが直接読めるデータではない。新規読み込みや変換コードは今回作成しない。

- `active_windows`は直接判定、`projectiles`は生成と寿命。WG06だけ親イベント状態から生まれる弾を別管理し、解決時に即取消す。
- `detached_ground`はWG18の所有。攻撃の後隙にも残る意図的な例外。床がある限り全ての通常技を無条件禁止する意味ではなく、安全経路を検証する。
- WG05の成功は受付[60,660)内のG0。早期終了時は予定されていたt720の珠も消す。失敗側900tick全体を成功後まで再生しない。
- WG06/14/16は成功・失敗で次カードを一度だけ起動するイベント状態。期限時点で受理済み命中を先に処理する。
- WG08/WT09のRECOVERYは変身の構え直しでHP攻撃不可。WG17/WT18の末尾RECOVERYも起上がりであり、反撃は別の`exposure`に明記。
- WT05の三つの窓は240tick周期の相対時刻。6周期後は通常ダメージの結果を一度だけ出し解除。無期限の元素要求ロックにしない本作案。
- WT17のLOCKと突進窓はF100を受理したsからの相対時刻。期限からの相対ではない。固定ルート28件にはこの条件付きルートを加算していない。
- WT03/17では衝突した最初の有効な駒だけを処理し、走路上の複数を一度に消さない。見た目の残像に衝突判定なし。
- WT19は二体のHP間の転送であり回復生成ではない。プレイヤー蘇生の仕様変更でもない。

## 3. 原作と本作の違い

| 論点 | 原作参考 | 本作の制作開始案 |
|---|---|---|
| 蝕破 | 遅れてHPを失い、特殊な貫通の観察記録もある | actorへ遅延予約、4上限。既存通常ダメージ処理。盾/無敵貫通を追加しない |
| 虚界力 | 元素/夜魂の手数が重要 | 物理1/元素2を受付。夜魂システム未実装を前提に無断追加しない |
| 障壁破壊報酬 | 原作に固定HP損傷とダウンの記録 | 初版は8秒の攻撃機会。固定最大HP損傷なし |
| 床切断 | 実際の戦場の縮小 | 左端1Uずつ3回。HP閾値で予約、間に通常技を置く。最小7U |
| 画面暗化 | 芽召喚に伴う暗い戦場 | 背景alpha0.18以内。必須情報は暗化しない |
| 盤面 | 全方向に動けるチェス盤 | 横8区画と上段足場。駒の移動の意味を保つ翻案 |
| 凍結 | 水/氷・反応と解凍が重要 | 実反応ならF加算、独自の霜印操作も有効。味方の炎で進行を妨害させない |
| チェックメイト | 原作の致死大技 | 通常大ダメージの失敗結果。ロノヴァの確定死は使わない |
| 相方蘇生 | HPを分けて相方を戻す | 現在HP半分まで転送、合計保存、全戦2回上限。原作回数の転記ではない |
| 週ボス全体 | 樹脂/週報酬等がある | 今回は報酬・週制限・難度数を決めない |

公式の資料とコミュニティの実戦記録を区別して各文書へリンクした。公式HoYoLABは動的・画像主体で本文の全図を読めなかった部分がある。対局のゲーム内説明画像は直接見たが、戦闘ムービーのコマ計測やモデルの四方向照合はしていない。将来の公開ボス情報が変わっても、本票を最新公式数値の保証として使わない。

## 4. Codexの制作順

最初に原作の構え/武器左右/人型と駒形態を参照し、動画URL・確認時刻・未確認箇所を残す。次に本体・武器・翼/尾・床・駒・試練対象を分離してキー姿勢を描く。透過/縮尺/足元ソケットを確認後、許可された範囲でロジック時刻へ接続する。先に技の秒数を絵の枚数へ固定してロジックを逆算しない。

源焔の最初の制作セットはWG02/03/10（炎剣・二薙ぎ・双刺突）とWG09（床切断）、対局はWT04（誘導）とWT17（凍結から衝突）を優先。成功後のWG17/WT18を同時に作り、気持ちよい反撃機会を先に比較する。

## 5. 必須の実行検証

### 源焔

三回切断を早い連続ダメージで予約しても一度ずつ解決すること。新左足場が先に分かり、消える床でUIや当たり判定がずれないこと。残留床が最小7Uを埋めず、三柱の20/50/80%配置が全て到達可能であること。落下からの安全復帰で同じfallEpisodeを二重請求しないこと。

Aの付与、120tick後の損傷、同actor30tick、床90tick、交代、死亡、満上限への新規付与を一つずつ記録。Gへの通常1/元素2が多段/反応/AIで不当に増えず、指定手数が実際に間に合うことを測る。成功と最終弾衝突が同tickでもWG17と失敗側が同時に始まらないこと。

### 対局

右向き/左向き・端・上段・ターゲット死亡でキングの走路を確認。ポーンの攻撃を避けながら正しい位置へ回れ、突進を跳んで空けられるかを実操作で測る。ポーンはプレイヤーの通路を塞がず、敵キングだけが衝突を受ける設計を検証する。

F100だけでクイーン大技が成功扱いにならず、その後のキング接触が必要であること。Fを未完了のまま放置した場合、凍結直後、突進中、両者死亡で正しく親castを取消すこと。霜印の予約が二重に始まらず、被弾中断で既に支払った進行を巻き戻さないこと。

WT19の180tick中にダメージを入れたとき、完了時の現在HPから転送されること。両者同tick0で勝利、予算0で永久退場、受取側最大値へのclamp、復帰actorGenerationで旧弾が復活しないことを確認。範囲攻撃は各個体へ一度ずつ通り、共有HPを二重減算しない。

### 共通

ソロ/同行AI/複数人、最大と最小画質、デスクトップ/狭い画面、保存/再接続/一時停止/新試行。通常J長押し・派生コマンド・E交代・Q光界と文脈操作が競合しないこと。全ての舞台装置は元の60技へ追加しない。実装範囲はCHAT_HANDOFF/AGENTSと最新ユーザー指示で確認し、この文書だけで技実装保留を解除しない。

## 6. 再実行できる索引検査の最小例

以下は保存JSONの構造・算術だけを再検査する。元の全検査のうち、文章/幾何/実機は対象外である。

```python
import json, hashlib
from pathlib import Path
p = Path('docs/weekly-boss-v1/MANIFEST_PRIMAL_GATE.json')
b = p.read_bytes()
m = json.loads(b)
entries = m['entries']
expected = {f'WG{i:02}' for i in range(1, 19)} | {f'WT{i:02}' for i in range(1, 21)}
assert len(entries) == 38 and {e['id'] for e in entries} == expected
fixed = [e for e in entries if e['kind'] == 'fixed']
assert len(fixed) == 28
for e in fixed:
    r0, r1 = e['recovery']
    assert 0 <= r0 < r1 == e['total_ticks']
    for a, z in e['active_windows']:
        assert isinstance(a, int) and isinstance(z, int) and 0 <= a < z <= r0
    for projectile in e.get('projectiles', []):
        assert all(t + projectile['ttl_ticks'] <= r0 for t in projectile['spawn_ticks'])
    for floor in e.get('detached_ground', []):
        assert floor['owner_state'] == 'WG18' and floor['may_outlive_cast']
d = {e['id']: e for e in entries}
assert d['WG17']['exposure'][1] - d['WG17']['exposure'][0] == 480
assert d['WT18']['exposure'][1] - d['WT18']['exposure'][0] == 360
assert 600 + d['WT17']['charge_window_offset'][1] < 960
print(hashlib.sha1(b'blob ' + str(len(b)).encode() + b'\0' + b).hexdigest())
```

この出力が上のSHAと一致すれば、少なくとも今回保存した索引と同じbytesである。変更後は古い検査結果を流用せず再検査する。
