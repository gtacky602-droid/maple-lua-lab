## 2. 読み方・例外の明示

- `active_windows`は直接の攻撃要求。`projectiles`は生成と寿命で、実衝突時刻とは別。端末弾は敵攻撃ではなくプレイヤー操作による装置作用。
- `recovery`は全てが攻撃可能な隙ではない。WN07/17の最後は起上がり、WN08・WP05/13は移行、WP16は保護準備。各 `hp_attackable_during_recovery` と本文を優先する。
- `exposure`は姿勢と攻撃先が安定した明示的な反撃時間。WN07[60,420)、WN17[60,660)、WP18[60,540)。WP18の最後の起き直しでもHP攻撃可だが、安定した8秒とは分ける。
- WN01炎/氷は同じ時間割の見た目・属性分岐で、別時間割数には含まない。WP01後半二払い、WP02二連短縮、WP07小弾の3つが時間割variant。
- WN11の散布は初期順序を炎t120・氷t180・水t240に固定。炎氷だけ360tickの床。本文の『各着弾』を水にも残留させる意味にしない。
- WN18の床はcastから独立した寿命管理。例外は床だけで、普通の弾を後隙まで残す許可ではない。上限4枚・同actorの環境hit間隔90tickを管理する。
- WP16のドームは次のWP17を守るため、WP16単体の終端を越える。親シーケンス所有で[60,720)、WP17の終端・死亡・中断で即判定消去、装飾のみ12tick退色。
- WN15は固定攻撃ルートではなく期限付き状態。期限tickに受理した有効な胸衝突を先に処理してから失敗判定。発射受付だけでは成功にしない。大技中断からWN17へ進んでも、端末のローカル操作後隙は既存入力仕様に従う。
- WN15の滅度機は4つ×4group。初版の消費groupは操作キャラの新規攻撃に加え、プレイヤーが対象指定済みのAI直接攻撃を認める。設置済みの周期hit・装飾・同group多段は別回数に数えない。本文の『補助できる』の具体化であり、AIが自動で照準射撃まで終える仕様ではない。
- WP08/10のリンク候補は相互排他。護衛は飼育未リンクの基本体、飼育は未保護の基本体。特殊役同士に盾・強化をつながず、循環する無敵集団を作らない。
- 心へ与えるP減少とキャラHPダメージは別経路。心が味方の回復範囲に入ってもPは増えない。敵の捕食と幕間破棄をプレイヤー撃破として加算しない。

## 3. 原作と本作の違い

| 対象 | 原作を参考にする核 | 今回選定した翻案 |
|---|---|---|
| 正機前半 | 元素装置とエネルギーブロック、二つの雷による停止 | 六装置を横配置、共有C、単独操作予約、C0の補給保険 |
| 正機後半 | 盾・端末・弱点・滅度機 | 物理と全元素で四基を破壊、低い足場に配置、普通の近接も盾へ寄与 |
| 正機大技 | 試練の失敗時に大きな危険 | 初版は通常大ダメージ。ロノヴァの確定死を使用せず、失敗後も盾0でHPへ攻撃可能 |
| 正機ダウン | 機体が崩れて集中攻撃 | 胸を近接が届く位置へ、安定した10秒。特殊移動スキル不要 |
| オアシス防衛 | 心を守る、撃破で進行、被攻撃で後退 | P25開始、受動+1/秒、撃破+3/+8、心被弾-4/-18、同時8体、初期波・節目波 |
| 増殖生命体 | 護衛元と支援先の役割、捕食、障壁、自爆 | 一役一主動作、循環支援なし、障壁の物理破壊、捕食連打は四打 |
| 守護者大技 | 保護の内部で広域危険をしのぐ | ドーム3つ、三脈動＋最後の一撃、終撃まで保護、8秒安定反撃 |

元資料を「完全再現」としない。原作の細かい耐性・必要元素・特殊移動・強制死亡・エネルギー回復を、本作の物理攻撃・光界ゲージ・死亡ルールへ無断で置き換えない。具体的な変更をここに明示して制作比較する。

## 4. Codexの制作・接続順

1. 既存台帳と最新ART_REFERENCE_POLICYを読み、正機の上半身/全身候補、守護者の暗色/緑候補の現況を確認。原作画像・映像・可能ならモデルを直接比較し、角度と未確認箇所を記録する。
2. 基礎モーションを作る。正機は肩→肘→掌の重い遅れ、全身起動、膝からの崩落。守護者は頭→胴節→尾のしなり、前肢の曲げ、潜行/浮上、葉冠の開閉。衣装と弱点を説明文だけで生成済み扱いしない。
3. 仮装置でC/G/矩陣/四基/予約、防衛P/出現/リンク/ドームの状態をレビューする。ゲーム処理の実装は保留解除の明示指示を受けてから。仕様を読むだけでは許可範囲は広がらない。
4. WARN・SAFE・端末照準・心・リンクを先に読める画面へ置く。巨大な機体、緑の粒子、ダメージ数字はそれらを覆わない。最軽量でも予兆と回収対象を残す。
5. 許可された段階で、実tickのLOCK/ACTIVE/衝突/消費/露出とポーズを接続。画面に光が出ただけでHPやPを変えない。
6. 無演出のログ検証→姿勢だけ→エフェクト→数字・音→低負荷/マルチ、の順に比較する。原PNGと軽量版を同一サイズで表示し、FPSではなく素材削減率だけを成果として混同しない。

## 5. プレイ試験で必ず確認すること（未実施）

- 全ての矩陣へ歩行とジャンプで到達可能。C共有の先着予約、二人同時決定、予約者死亡、退出、再接続、旧epochの回収で二重消費/増殖しない。
- 風装置なしでも大ビームに常設の逃げ道がある。巨大な腕や脚を必ずすり抜けられるという未確認前提に依存しない。
- 普通の攻撃と自動端末がGを同tickに0へした場合、試練は一度。G0で自動端末がHPを削り続けない。主人公の攻撃を入力しなくても全戦勝利する構成にしない。
- 四基へ近接で到達し、4group×4を24秒内に処理できるか。最後の照準・発射・飛行時間を含めて測る。無理なら距離/期限/必要groupをテスト差分として改訂。
- 中断失敗時の通常大ダメージが実質的な不可避即死になっていないかは威力調整段階で確認。確定死版との違いをHUDでも説明する。
- 防衛の波が8体上限で詰まらない。既に満員なら特殊役が必要とする基本体枠を予約する。護衛/飼育の両方が無敵にならない。早く倒せば短く終わるが必須モーションが無意味にならないかを観察する。
- P0・P100・全滅・同tick複数撃破・爆発前撃破・捕食・幕間cleanup・旧弾で進行/報酬が二重計上されない。
- 取り巻きはシンプルな一動作でも役割が分かる。自爆予告を雑魚のダメージ数字が隠さない。実障壁を導入する場合は脱出経路を探索してから採用。
- ドームの見た目と内部判定の一致、各actorの体格、AI退避、マルチ同時入場、保護境界での移動を試す。人数制限なし。終撃前に保護が消えない。
- 旧フェーズの床・取得物・支援・弾は一度だけ消える。ボスHP0時は勝利を優先し、死亡後に未実行の攻撃が発火しない。人数HP倍率・他人蘇生・週1制限・樹脂は追加しない。

## 6. 最小の再実行例（索引のみ）

```python
import json
from pathlib import Path

p = Path('docs/weekly-boss-v1/MANIFEST_SUMERU.json')
m = json.loads(p.read_text(encoding='utf-8'))
entries = m['entries']
by = {e['id']: e for e in entries}
expected = {f'WN{i:02}' for i in range(1,19)} | {f'WP{i:02}' for i in range(1,19)}
assert len(entries) == len(by) == 36 and set(by) == expected
fixed = [e for e in entries if e['kind'] == 'fixed']
assert len(fixed) == 30
assert len(m['variants']) == 3
for e in fixed + m['variants']:
    n = e['total_ticks']
    r0, r1 = e['recovery']
    assert type(n) is int and 0 <= r0 < r1 == n
    for a,b in e['active_windows']:
        assert type(a) is int and type(b) is int and 0 <= a < b <= r0
    for t in e['lock_ticks']:
        assert type(t) is int and 0 <= t < n
    for field in ('projectiles','obstacles'):
        for q in e.get(field,[]):
            assert q['ttl_ticks'] > 0
            assert max(q['spawn_ticks']) + q['ttl_ticks'] <= r0
    if 'exposure' in e:
        a,b = e['exposure']
        assert 0 <= a < b <= r0
    if 'parent' in e:
        assert e['parent'] in by
f = by['WP16']['protected_fields'][0]
start = f['spawn_ticks'][0]
end = start + f['ttl_ticks']
offset = by['WP16']['next_offset_ticks']
assert end == offset + by['WP17']['total_ticks'] == 720
for a,b in by['WP17']['active_windows']:
    assert start <= offset+a < offset+b <= end
for id_, duration in [('WN07',360),('WN17',600),('WP18',480)]:
    a,b = by[id_]['exposure']
    assert b-a == duration
print('Design index checks passed; gameplay/geometry/engine NOT tested.')
```

原作の全モーション網羅や完成を宣言しない。現段階の成果は、作画と後続の許可された実装を始めるための36カード・3分岐・状態契約と、索引の静的検査である。
