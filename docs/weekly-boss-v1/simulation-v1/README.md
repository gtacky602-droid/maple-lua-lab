## 結論と範囲

**源焔の主 WG05/WG16 は「単独キャラの物理通常でも試練を突破できる」という意図を現行の数値では満たさない。** ほかに、鯨の核の高さと受付時間、対局の凍結後の移動、召使のヒーラーなし返済時間に、接続・配置・テンポの見直し点がある。

これは設計値の時間進行モデルをPythonで実行した結果。**ゲーム本体のLua、14戦の完成ボスAI、画像、実機、ネットワークを実行した結果ではない。** 227項目全部の幾何を再現したものでもない。敵HP・攻撃倍率・難度別DPSが未確定なので、討伐時間や人間の勝率は算出していない。元設計の数値・ゲームコード・画像・報酬・セーブは変更しない。

## 1. 実行内容と条件

12個の時間制限設定（元仕様9＋修正候補3）を、初期位置21通り（0〜10U、0.5U刻み）、反応遅延4通り（0/0.2/0.4/0.6秒）、一度の途中休止3通り（0/1/2秒）、1/2/4人分の基礎通常攻撃で比較。6設定には理想的な同行補助モデルを追加した。合計**10,584ケース＝元設定8,316＋候補2,268**。成功数はこの人工条件集合の件数で、プレイヤーの勝率ではない。

14戦それぞれから選んだ反撃機会を距離1/3/5Uの42条件で比較。トワリンの区画移動、王狼の退避、低い波、ジャンプ、温度、契約返済、防衛進行、最初の突進誘導を別モデルで確認。共有予約24順列、回復先払い1,000例、敵同士のHP譲渡1,000例、禁令の入力由来9例等も参照契約として検査。モデル自身の単体テスト**11件成功**。

`core.lua`から移動210px/秒、通常CT0.6秒、開始時と0.12秒後の二打、射程125px、標準縦距離75px未満を使用。60Hzでは第二打は8tick後。ジャンプ初速650px/秒、重力1300px/秒、半陰的更新。U=88px。資料値は手動転記した`fixtures.json`に固定し、元ファイルのblob SHAと固定コミットを記録。

移動override、装備加速、スキル差分、敵の攻撃・被弾硬直・接触妨害は期限モデルに含めない。対象は地上・固定位置。一度の途中休止は回避などによる時間損失の感度試験で、実際の攻撃を避けた証明ではない。単純な順次処理を使い、世界全体の最適戦略は探索していない。

同行補助モデルは基礎actor2の通常（0.7秒間隔、0.15/0.23秒の二打）、同位置・指示対象への完全な追従を仮定。**現行の同行AIや固有スキルを動かした試験ではない。** 補助が死亡/無反応の場合は単独モデルと比較。2/4人も実ネットワーク・別々の立ち位置の再現ではない。

## 2. 修正優先度

### P1 / S-01: 源焔のG24を通常だけで崩す時間が足りない

参照: [源焔の主](../LORD_OF_ERODED_PRIMAL_FIRE.md) WG05/WG16/共通G、`core.lua`通常攻撃。

Gは通常1、元素2。同じcast/targetは一度、同actor24tick以上。通常の二打を二回分にはできない。

- WG05受付[60,660): 10秒。受付同時に攻撃を始めるモデルでは17回分。
- WG16受付[60,600): 9秒。同モデルでは15回分。
- 24回目: `60+23*36=888tick`、技開始14.8秒、受付から13.8秒。移動・反応時間がなくても超過する。
- 先行入力した第二打が受付直後に当たる場合も別に36位相×2窓=72条件で確認。9秒窓は最大16、10秒窓は最大17。24回目の最速は受付から820tick=13.67秒。先行入力でも不足は解消しない。
- 単独は両設定とも0/252成立。理想同行補助ではWG05が252/252、WG16が232/252成立。**AIが順調に殴っていると見えなくなる、編成救済の穴。** 全ボスが討伐不能という意味ではなく、通常だけで試練を成功させる経路がない。失敗後の通常戦は仕様上残る。

修正候補A: **G12、受付12秒**。[60,780)の単独252条件が全成立。技開始7.60〜10.10秒に完了、最悪余裕2.90秒。候補B: G24のまま受付18秒。[60,1140)なら全成立、最悪余裕1.70秒。無攻撃・平地モデルでの余裕で、実戦保証ではない。元の仕様・演出尺はまだ変更していない。

### P1候補 / S-02: 鯨の核の高さと地上近接の接続

[鯨](../ALL_DEVOURING_NARWHAL.md) WV11は核z0.9U=79.2pxを「地上近接が届く」と記す。core標準近接は縦距離75px未満。`hitTop/hitBottom`なしの点ターゲットとして接続すると不一致。**完成コードの不具合ではなく、未実装の当たり領域の指定に依存するリスク。**

描画中心は維持し、攻撃対象の下端を0.8U以下に明示する等で解決する。全通常攻撃の縦射程を広げて帳尻を合わせない。

受付[60,240)は3秒で、必要4castの最短は受付から1.8秒。対象が届く前提なら、中断なし84条件は全成立。一度の1〜2秒休止を加えると単独162/252条件成立、最悪1.3秒超過。遠くで開始したり回避を重ねたりすると急に厳しくなる。受付4.5秒への延長等は次の比較候補で、今回はその候補の時間割やVFXを変更していない。

### P2 / S-03: 対局の凍結後、最初の誘導に届かない配置

[対局](../GAME_BEFORE_THE_GATE.md) WT17はクイーンx6U、キングx2U、凍結成功sから72tick=1.2秒で走路固定。左の霜印をx0.5Uに置く例で、クイーンの右x6.5Uへ行くには528px、151tick=約2.52秒。反応0でも足りない。

霜印のxは元仕様で未指定。0.5Uはテスト仮定。**最初の誘導の不成立例であり、右の装置・再誘導・別プレイヤーでも全試練が必ず失敗するという意味ではない。**

左/右×反応4通りの8条件は、元72tick固定で左4条件不成立、右4条件成立。固定まで210tickの候補なら8条件成立。突進開始/終端も138tick後ろへずらすと最遅s600でも終端894<期限960。再試行開始上限は804→666への変更が必要。代替は「誘導準備完了」の操作後に狙いを固定すること。

### P2 / S-04: 召使のヒーラーなし返済は長い

[召使](../THE_KNAVE.md)の返済灯では、D25%は45+4×60=285tick=4.75秒、D50%は45+9×60=585tick=9.75秒。中央から有効範囲へ歩く時間と反応0.3秒を加えると約6.72秒／11.72秒。被弾・回避・キャンセルは含まない。

返済不能ではないが、最大まで重なると長く攻撃から離れる。毎回操作するのでなく範囲内での継続返済へ統一するか、最大時の返済速度を上げる案がある。HPを回復する万能装置へ無断変更しない。

### 接続ゲート / S-05: 禁令・共有予約には入力元とownerが必要

[偽月](../DOCTOR_FALSE_MOON.md)WM09を座標変化だけで判定する意図的な反例モデルでは、旧castの移動、吹き飛ばし、同期補正、AI移動の4種が誤違反になる。入力元を分けた参照モデルは9例を分類できたが、**本体への接続は未検証**。

正機の共有端末も、予約者死亡/退出時の解放がない反例モデルでは10秒後も他人が使えない。解放を付けた参照モデルは進行する。これを既存実装の観測バグと呼ばない。

`encounter_interact`には対象、押す/保持/照準確定の種別、保持時間、予約owner、キャンセル理由、解放期限を必須データにする。J保持/E交代/Q光界を奪わない。

### 反撃時間と接近

距離5U、射程125px、移動210px/秒、反応0.3秒では初撃まで1.8秒。1〜1.2秒の短い後隙へ遠方から戻ると一発も入らない。ただし一般ボスは後隙以外にもHP攻撃可能なことがあり、短窓を全て延長すべきという結論ではない。

同条件で召使3.6秒は通常実hit要求6回、8秒は22回、10秒は28回、12秒は34回。CTが初めから使え、固定対象へ攻撃し続けるモデルの値で、実DPSではない。トワリンWD03の短窓はHPでなく体勢用として明記した。

### ジャンプと保護領域

長押しジャンプの最高点157.08px=1.785U、滞空60tick。1tickだけ押す場合は25.72px。1.4Uへは最低13tick、1.6Uへは最低17tickの保持がこのモデルでは必要。1.8Uは届かない。上段を対処に使うなら、長押しと動線を学べる導線が必要。

アペプの保護内側は高さ1.5U。中でフルジャンプすると足元自体が上限を超えるので、仕様どおりなら保護を外れる。意図的な形状の結果でバグ認定ではない。退避後の同行AIの不要なジャンプを抑え、見た目の屋根と安全域を一致させる。

## 5. 再現方法と次の工程

このディレクトリで:

```bash
python simulate.py --out results
python -m unittest -v test_simulate
python prefire_boundary.py
```

標準ライブラリのみ。全条件CSV、42反撃条件CSV、詳細JSON、代表traceを生成する。先行入力の72ケースは別JSON。fixtureは手動転記で、実行時に最新の原仕様を自動抽出しない。仕様更新後は入力固定コミットを上げ、差分を再確認する。

次の採否順: (1)源焔の物理代替、(2)鯨の核の高さ/受付、(3)対局の凍結後の移動、(4)文脈操作とowner解放の統一、(5)Codexで通常だけ・同行無反応から実プレイし、次に有効AIと四人と同時攻撃へ拡張。

この報告だけで元仕様を自動修正しない。検証スクリプトは設計補助で、ランタイムから読ませない。全227項目の回避、全戦の討伐時間、画面の可読性、実機API/ネットワーク/FPSは後続試験が必要。
