# 全地域ルート v2 を設計室へ取り込む

1. 設計室の「変更案」で「更新」を押し、全地域ルートv2 [CROSS/all] を開きます。ドラゴンスパイン `teyvat:6599` ↔ 璃月 `teyvat:34` など、別の地域を結ぶ線は「接続グラフ」で確認できます。
2. 差分を確認し、必要な修正を行ってから、ローカルUIで採用します。
3. 採用後に次のコマンドを実行すると、現行データを読み直し、次の地域だけを最新revisionの変更案として保存します。設計室に戻って「更新」を押します。

```powershell
python -X utf8 -m tools.field_editor.stage_world_routes --project "C:\path\to\current\project.json"
```

変更案が未採用の間は次の地域案を作りません。別の編集を先に採用して地域案が古くなったときは、設計室で差分を再作成して確認してください。既存の手動案も、採用時には最新revisionとの差分を確認します。

## 対象と順序

CROSS → 璃月 → 稲妻 → スメール → フォンテーヌ → ナタ → ナド・クライ → スネージナヤ → 沈玉の谷 → 淵下宮 → トゥニギの黒淵 → 往日の海 → オシカ・ナタ → ノヴォキッチェヴ → 層岩巨淵・地下鉱区 → 古の聖山 → 空の神殿 → 霜月。

沈玉の谷・トゥニギの黒淵・オシカ・ナタ・ノヴォキッチェヴは、それぞれ地域案の前に設計分類を確認します。モンド本土・ドラゴンスパイン・ドーンマンポートのフィールド設定と敵配置は対象外です。

ナド・クライ特別地域と期間限定の3地域は、公式地点に対応していない32スロットを資料に残します。保留の83地点とナタの3地点ブロックには、本線への入口を追加しません。CROSSのC09は片側だけに公式階層が付いており、通行方法と入口の確認を待ちます。

## 検証と保護

- 付属の `make_editor_proposal.py --include-review --review-note` に現行データのコピーを渡し、エディタのモデルで検証します。
- 採用済み・手動案にある同じ接続先ペアは保留します。既存の敵ID・Lv、配置、別の手動編集と衝突した場合は生成を止めます。
- 通常の徒歩経路の両端は同じ公式座標系・階層に絞り、明示された船・鉄道・潜水などの移動方法を保持します。個々の入口、崖、帰還手段には実機での確認が必要です。
- 実ポータル位置と敵の出現座標は未設定です。座標が未設定の接続・敵配置はランタイム用出力に含まれません。
- 配布元の設計資料と生成入力は `design/field-editor/teyvat-routes-v2/` に保存しています。閲覧HTMLやスクリーンショットは元ZIPの展開先を参照してください。

検証用コピーで全工程を確かめる場合は、同じコマンドに `--audit "work/world-routes-audit.json"` を追加します。各地域のrevision、操作数、保留した接続と理由が保存されます。

- 最新mainは `555b7cd`。稼働中の設計データは rev 0 で、保存済みの手動変更案7件を比較対象にしました。
- 配布ZIPは73ファイルのSHA-256が一致し、付属の44テストが通過しました。Windowsで再現したテスト用JSONの文字コードだけをUTF-8に指定しました。
- 正本のコピーでCROSSを含む22段階を直前の採用後のrevisionから生成し、接続 564 本、敵配置 2026 件を検証しました。実座標未設定の接続・敵配置のランタイム出力は0件でした。
- 接続候補862本のうち298本を保留しました。手動案との同一地点ペアは140本で、このうち20本は公式階層との不一致にも該当します。残る保留は公式階層などで徒歩条件を満たさない候補と、未対応スロットの候補です。
- 実際の設計室ではCROSSの20本を保存し、6599↔34を差分と接続グラフで確認しました。ランタイムの通行・敵出現は未検証です。
