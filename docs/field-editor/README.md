# テイワット・フィールド設計室

既存のLuaゲームと別プロセスで動く、公式地形・ワープ/神像を使う設計エディタです。通常8地域・高難度9地域・隠し3世界と、既存カタログの独立マップに対応する**24枚の定義**を用意しました。ゲーム完成数・実装済み狩場数を増やす変更ではありません。

## 起動

リポジトリのルートで、Python 3.10以上を使用します。アプリ自体はPython標準ライブラリだけで動き、Lupa・Node・APIキーは不要です。

```sh
python -m tools.field_editor.server
```

[http://127.0.0.1:8770](http://127.0.0.1:8770) を開きます。終了はターミナルでCtrl+C。既存ゲームの `server.py` / 8769とは独立しています。Windowsでもリポジトリルートから同じコマンドで起動できます。

別データで試す場合：

```sh
python -m tools.field_editor.server --port 8771 --data work/my-field-design.json
```

`--data` に未作成ファイルを指定すると、未設定の新しい設計から開始します。正本をコピーして比較したい場合は、先に `design/field-editor/project.json` を別ファイルへコピーしてください。

## 操作

1. 左の地域を選択。初期表示はカタログの公式モンド所属 **51地点（ワープ45・神像6）**です。通常部分だけを見たい場合は「地図の範囲 → 通常地域のみ」。ドラゴンスパインとドーンマンポートも個別選択できます。
2. 中央は公式配信タイル。ドラッグで移動、ホイール/＋/−でズーム、「全体」で表示範囲を復元します。密集時もマーカーは残し、重なるラベルだけ間引きます。右下の「地点IDから探す」からも移動できます。
3. 地点をクリックし、右で名前・Lv・敵・クエスト・地形・メモを編集。「変更案を保存・差分確認」で案をディスク保存し、**金色の提案レイヤー**に表示します。
4. 差分と地図を確認し、確認欄をチェックして「採用して正本へ保存」。既に確定した項目の変更・削除には、別の「確定済みの値・接続を変更」の確認も必要です。
5. 「接続モード」をONにし、小さな丸い接続ハンドルから別ノードへドラッグ。双方向/一方通行、Lv、クエスト、隠し、船、一時条件、2Dフィールドの入口/出口座標を設定します。近い点の自動接続は行いません。線のクリックから編集・削除できます。
6. 「接続グラフ」ではノード本体をドラッグして配置を保存できます。公式座標とは別の `graph_layouts` を変更する案です。「攻略ルート」は推奨Lvの順に並べた有向ネットワークです。未設定Lvは左側。循環・分岐・合流・地域間接続を保持します。
7. 図鑑で「敵系統 → 地域別Variant」を登録し、採用後にフィールドへ配置します。系統は既存のヒルチャール・水/炎スライム・遺跡守衛の**候補素材参照**を初期登録。根拠がないHP・Lv・EXPや公式地点名を埋めていません。
8. 敵の基準LvはVariant側。配置画面でLv/継承したステータスを表示します。フィールド側の個別Lvは「特殊個体」をONにした場合だけ許可。Variantの変更時に影響フィールド数・IDと維持する特殊Lvを差分画面に表示します。
9. Ctrl+Z / Undoで未採用案のプレビューを解除。採用済みの直前変更なら逆差分を新たな履歴として保存します。Ctrl+Y / Redoで復元。入力欄内では通常のテキストUndoを優先します。任意の古い変更は履歴の「巻き戻し案」で差分を確認してから採用します。後続変更と衝突する巻き戻しは拒否します。
10. 「接続を検査」で到達不能・行き止まり・一方通行の帰還不能・Lv飛び・必須経路の欠落・地域Lv基準から外れる敵配置を確認します。意図した例外は理由付きの提案として登録・採用できます。

採用履歴から、値を変えずに「実装済み → 検証済み」の状態変更を行えます。実装コミット・検証記録などの出典が必要です。エディタで採用しただけで実装済み・検証済みにはしません。

## Lv基準と不明情報

- 通常モンド：Lv1〜20。
- ドラゴンスパイン：探索35、通常敵40〜55、最深部60。
- ドーンマンポート：探索150、通常敵155〜170、最深部175。
- 全体上限：200。これら3地域の基準は今回の明示指示に従います。**各地点にそのLvの敵を自動割当する意味ではありません**。
- 他地域の既存Lv案は `COMMON.md` / `SIX_DECISIONS_DRAFT_V01.md` に従い `proposed`。隠し世界は未設定。入場制限へ自動変換しません。
- 51地点は公式 `area_id=1` の全集合です。その中の雪山13・港側13は、IDを明示した**設計上のグループ分け**で、公式の地域IDや座標の変更ではありません。この所属分け自体は `membership_state=proposed` として位置レビュー対象を明示しています。
- 名前がカタログにない地点は一律「名称未確認」。編集できる「設計上の地点別名」と、公式名称の確定を混ぜません。
- `point_group.group_id/floor_id` を保持し、階層付きノードを表示します。`point_group` がないことだけで地上とは断定せず「階層未確認」にします。公式の地下平面図を地上タイルで代用したとは扱いません。

## ChatGPT・Codexとの相談

下部の設計チャットは**オフラインの限定構文変換**です。外部LLMとの自由対話は接続していません。APIキーを要求したり、ChatGPTに直接ローカルファイルを書けると仮定したりしません。

対応例：

- `teyvat:3の推奨Lvを8にする`
- `teyvat:3とteyvat:7をつないで`
- `teyvat:3からteyvat:7へは一方通行にして`
- `モンドのヒルチャールをLv5に統一`（該当地域の登録済みVariantが対象）
- `teyvat:3にヒルチャールを10体配置`（Variantの基準Lvを参照）
- `teyvat:3にLv8の特殊個体のヒルチャールを10体配置`（明示した個別Lv）
- `璃月の全フィールドLvを比較`、`接続樹形図を表示`

同名の地点・Variantが複数あれば更新せず候補を返します。未知の地名は地理から推測しません。候補ボタンで地図を確認し、「選択中の地点を明示的な対象にする」を選んで再送できます。複数の同名敵がある場合は図鑑/変更JSONで `monster_id` を指定してください。一般的な自由文や曖昧な「少し難しく」はJSON/手動編集で具体化します。

ChatGPTから現在の設計データを参照するには、エディタ上部の「ChatGPT連携」を開き、[Windowsでの接続手順](CHATGPT_SETUP.md)に沿ってSecure MCP Tunnelを設定します。許可されたアカウントからは変更案も送れます。採用するときはローカルの設計室で差分を確認します。

ファイルを使う場合は「ChatGPT相談用Markdown」または「地域別設計JSON」を渡し、最新revision付きの変更指示JSONを取り込んでレビューします。正本は `design/field-editor/project.json` です。stdio MCPとHTTP APIの設定は [API・MCP](API_AND_MCP.md) を参照してください。

## 出力

「エクスポート」から以下をダウンロードします。

| 出力 | 内容 |
| --- | --- |
| 地域別設計JSON | 全地点、公式由来のID/座標、名前・階層の未確認、敵、Lv、項目別決定状態、接続、関連履歴、地図版・取得元 |
| ChatGPT相談用Markdown | 確定/未決定、敵、接続、地域Lv基準、直近の変更 |
| 変更指示JSON | 表示中の提案。Codex/API/画面から再取込可能 |
| 重ね合わせPNG | 表示範囲にID・Lv・敵・精鋭を描画。提案を含めた場合は画像内に明記 |
| 配置CSV | 敵ID/名・Lv・数・分類・採用状態・精鋭/地方伝説メモ |
| 接続JSON | edge_id、方向、移動方法、条件、出入口 |
| 実装用JSON | 承認済み項目のみ。未承認のVariant/配置/接続を除外し、承認済みの継承値を解決 |
| 整合性レポートJSON | 通常8・高難度9を含む地域基準、グラフの警告と承認済み例外 |

設計JSONの再取込は追加・更新を**提案**にします。削除は変更指示JSONで明示します。PNGはタイル読込が完了した場合だけ出力し、欠落タイルを含む完成画像を黙って保存しません。手動画像は「画像読込」で公式座標の左上・右下を指定して較正できます。初期の外接範囲を正しい較正値とはみなしません。手動画像・較正値は当該ブラウザ表示中のみです。

ランタイムJSONはLuaで読み込める単純なJSONです。**既存ゲームへ自動取込するコードは加えていません**。採用された配置を取り込み、発見/帰還/戦闘/保存を検証する工程は、エディタの採用と別に管理します。地域をまたぐエッジは設計/接続JSONに保持しますが、地域単位の実装用JSONでは両端が対象地域内のエッジだけを出します。全地域の実装用統合出力は「全地域ゲーム実装用JSON」、またはAPIの `export_map(map_id="all", format="runtime")` から取得します。

## 正本の構造・地域の追加

[DATA_MODEL.md](DATA_MODEL.md) に分離境界、項目別の出典、トランザクション、マップ定義追加手順を記載しました。新地域は `design/field-editor/maps/*.json` を追加してサーバーを再起動すれば一覧に出ます。新しい公式マップのメタデータ・確認済みノードをその定義内に含められるので、プログラムの地域分岐を増やす必要はありません。

## 検証

```sh
python -m unittest tools.field_editor.test_editor -v
python -m tools.field_editor.build_schema
```

ブラウザ検査にはNodeとPlaywright・Chrome/Chromiumを使います。`tools/field_editor` で `npm install --no-save playwright` 後、リポジトリルートで実行します。

```sh
python -m tools.field_editor.run_browser_checks
```

環境によって `CHROME_PATH` にChrome実行ファイル、`PLAYWRIGHT_MODULE` にPlaywrightモジュールのパスを指定できます。Python検査のJSON Schema検査のみ任意依存の `jsonschema` を使い、なければその検査だけskipします。ブラウザ検査は専用一時データを使用し、正本・ゲームセーブを変更しません。結果は `evidence/field-editor/`、公式地形を含むスクリーンショットはGit対象外の `work/field-editor-qa/` です。

## 未取得・制約

全地域の**仕組み**と既存873ノードの参照には対応しています。カタログに独立した所属がない高難度地域や、地点0件の期間限定マップの座標を捏造して補ってはいません。公式の日本語地点名、未取得の地下平面図、過去イベント世界の地形は今後の確認データ追加が必要です。地図の網羅確認完了やRPG本体への実装完了ではありません。

静的な接続検査は条件を満たした場合の到達可能性です。実プレイヤーのクエスト状態・期間条件を含む攻略完走の証拠ではありません。`can_travel` / APIではファストトラベル時のみ未発見先を拒否し、通常の移動での初訪問は可能にしていますが、ゲーム本体への導入と実プレイ検証は別です。現在のストレージは単一JSONを原子的に置換し、履歴・提案を同一トランザクションで保存します。大規模な共同編集/大量履歴ではDB移行を検討してください。

公式地形・配布条件・取得方法の記録は [MAP_PROVENANCE.md](MAP_PROVENANCE.md)。公開再配布の許可は未確認なので、タイル・公式画面をGitへ同梱していません。今回のCloud環境では共有プレビューの中継が起動せず、上記コマンドで動くローカルWebアプリを納品しています。
