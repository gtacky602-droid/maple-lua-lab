> **2026-11-17 最新の適用範囲**：この文書は、**完成を目指すWeb/Lua版を星々の幻境に移植するときのベータ先行範囲**についての検討記録。本人の最新指示により、**Web版はLv200・通常8地域・高難度9・隠し3・全ボス・全クエスト・全技までCodexが全部制作**してよい。Web版をLv80でカンストさせたりスメールで開発停止したりしない。Web全体の正式な制作指示は [WEB_FULL_BUILD_DIRECTIVE_20261117.md](../../WEB_FULL_BUILD_DIRECTIVE_20261117.md) を優先する。


## 採用する方向と、まだ提案の部分

**本人が直近で了承した大枠**：「スメール編までを公開テストとして1回公開する」→「その後はアップデートで拡張する」。さらに、以前『理想的』と表現した**Lv80でいったん上限に達しても、高難度マップの寄り道・装備厳選・繰り返し戦えるボスで遊び続けられる**構成を良しとした。

**本書で実装前提として整理する方向：**
1. 一般向け公開テストは1回。最初にモンド/璃月/稲妻/スメールの4地域が一本のRPGとして遊べるようにする。
2. **最初の公開範囲ではプレイヤーLv80を一時的な到達上限とする方針**。プロジェクト全体のLv200上限は変更せず、フォンテーヌなどの地域追加と同時に遊べるLv帯を順次広げる。
3. **Lv80後の活動を公開版の重要要件にする**。高難度マップの寄り道、装備更新、繰り返し挑めるボス、日課・累計EXP記録を主な継続理由にする。カンストした瞬間に遊びが終わる設計にはしない。
4. プレイヤーの育成・装備・クエスト・発見状態は**アップデートで原則継続利用する設計方向**。保存データの移行仕様は公開前に、実機で実現可能か検証して明示する。無断の初期化を予定しない。

**個別数値・実装方式は未確定：** 保存APIのトランザクション/容量、ランキングの開始日時や掲載形式、上限到達後のEXPの将来換算、ボスの完成数、特別マップ全区画の収録、公開日の具体値など。以下はCodexへ渡す優先順の提案であって、ユーザーが全行を個別承認した意味ではない。

## Lv80超過EXPと次地域の追加（方針と提案を区別）

- **本人が意図する方向**：Lv80でも狩りやボス周回を続ける価値を作る。上限後のEXP取得記録を失わない。
- **推奨する処理**：`level_cap_current_content=80` と`game_level_cap_target=200`を分離。`overflow_exp_at_cap80`の履歴を保持し、次のフォンテーヌ配信で上限がLv100になっても古い超過EXPを自動換算してLv81以上を飛ばさない。通常EXP進行は新Lvで再開し、履歴は累計EXP記録へ保持する。
- **セーブの設計原則**：`schema_version` と固有アイテムUID、初回報酬フラグ、個人クエスト進捗を保つ。新地域配信で旧地域の報酬・キャラ・装備・発見・ランキングの出所が消えたり二重付与されたりしない。保存/APIが未検証なので公開前の移行リハーサルを実施。
- **公開テストと正式EXPランキング**：個人の生涯EXP履歴は保持する。一方、正式ランキングはテスト記録とは別の集計開始日を設ける**B案を第一候補**とし、週間EXPランキングも併設検討。ランキング開始日、リーダーボードAPI、既存データの表示名と区切りは公開前に確定・告知する。過去の個人EXPを消すという意味ではない。
- テスト参加者へ、実装済み範囲、Lv80一時上限、超過EXPの使い道、セーブ移行の保証範囲、ランキング区切りを**公開前に明記**する。
- 有償のEXP2倍ポーションはゲーム内で認可・規約が確認されるまで販売する前提にしない。
