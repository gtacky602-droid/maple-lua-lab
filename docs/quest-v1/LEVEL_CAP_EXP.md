# Lv200暫定上限と超過経験値の記録方針（2026-11-17）

状態：**Lv200を現在の育成上限にすることは本人が明示した決定**。Lv200到達後の超過経験値を記録する案は本人からの積極提案。以下の「記録用・自動繰越しない」「保存形式」「UI」は、将来の経験値バランスを守るための**追加設計案**であり、個別の実装許可・確定仕様ではない。

## 目的
現時点のゲーム全体のレベル上限をLv200に置き、将来のアップデートで上限を延長できるようにする。ユーザーの懸念は、Lv200到達後にため続けた経験値をそのまま解放すると、次のレベル帯を飛ばしてしまい、新地域のEXPバランスが成立しなくなること。

## 確定した判断と保留
- **本人決定**：当面のプレイヤー／旅人／共有仲間レベル上限は **Lv200**。将来の更新で引き上げる可能性を残す。
- **本人提案**：Lv200で受け取った「超過経験値」を記録しておきたい。
- **本書の推奨案（要確認）**：獲得量を記録するが、現在の戦力・Lv・スキルには反映せず、将来の上限拡張でも**自動でレベルアップへ繰り越さない**。記録をどう活用するかは拡張時点で別途判断する。
- Lv200は**上限**。Lv180のSK60「七律開天」条件は別であり、Lv180を最終キャップにしない。装備のitemLv220上限案はキャラLv200の上限と別。敵Lv200・装備itemLv220の既存参照モデルをLv200正式キャップの根拠にしない。
- 現行の必要EXPテーブルは未確定。上限変更時は新しいテーブルと既存記録を分離し、古い累計から暗黙にLvを再計算しない。

## 進行モデル案

状態はプレイヤーの共有成長に一つ持つ。仲間別の経験値カウンタは追加しない。

- `level_cap = 200`：将来の上限変更を見据え、設定値として一箇所で管理。
- `current_level`：1〜200。200より上へ上がらない。
- `current_exp`：200未満で、次のレベルまでの進行を示す。到達時は`0`または`null`という表示・保存上の表現を固定する（未決）。UIは常に`MAX`。
- `overflow_exp_earned`：**Lv200到達以降に実際に獲得した経験値（移行時の超過分を含む）の累計記録**。使えるEXP残高・次レベルへの予約権ではない。
- `overflow_exp_cap_epoch`：どの上限世代で積算されたか区別する。初期はLv200世代。上限変更後は過去の記録を保持し、新キャップに到達したとき別世代を開始する（保存コストと移行方式は未決）。

### XP獲得の優先順
1. 討伐、クエスト、デイリーなど、通常の経験値付与経路で**権威側が確定した最終経験値**を一度だけ受け取る。通常のレベル差・報酬の補正を適用した値を使う。獲得源を重複カウントしない。
2. 現在Lv200未満なら、必要なEXPを使ってLv200まで上げる。1回の付与で複数Lvをまたぐ場合も通常の繰返し昇格処理を通す。
3. **同じ付与でLv200に到達し、余った分がある**とき、その余りを`overflow_exp_earned`へ加える。
4. すでにLv200なら、正常に付与されたEXPを`overflow_exp_earned`へ加え、Lv・通常成長値を変えない。
5. 記録時には二重付与防止のイベントIDと保存成否を扱い、保存失敗・再送・マルチAI撃破でも二重加算しない。

例：Lv199からLv200まで残り40EXPの状態で150EXPを受け取ったら、Lv200へ上がり、超過記録へ110EXPを加える。次の敵で50EXPを受けたら、記録が160EXPになる。これは例示であり、必要EXP数値の決定ではない。

### 期間・UI・将来の拡張
- HUDは「Lv200 MAX」。任意のステータス欄で「Lv200到達後の累計獲得EXP：12,450,000（記録のみ）」などと表示する。
- **「EXP貯金」「次Lvへ持越し確定」といった誤解を招く表示を避ける**。上限拡張時の自動移行は保証しない旨を短く明記する。
- 将来の上限解放で`level_cap=220`などへ変更する場合、`overflow_exp_earned`は履歴のまま保持し、新しい通常EXP進行は原則0から始める案。過去分の記念報酬や限定的な繰越しを検討するなら、別の変換ルールと上限・説明・移行コードを明示したアップデートで初めて実施する。**保存された累計を暗黙に一括換算しない**。
- 記録の累計が大きくなり得るため、32-bit整数や浮動小数での精度喪失を前提にしない。保存・信号・JSON/数値型の上限とコストを幻境実機で検証。必要なら固定幅の上位/下位または文字列化/飽和値と別フラグ等の方式を選ぶ。実機の永続保存容量・原子処理は未確認。
- ログを撃破ごとに保存し続けるのではなく、**集計値のみ**を保持するのが初期案。EXP付与重複防止は現行の権威イベントID方式に沿って実装する。
- EXP倍率消耗品が実装される場合、Lv200での使用をどう扱うか別途決める。**記録だけを増やす目的でプレミアムなEXPアイテムを消費させない**。到達直前の残時間・倍率の扱いもテスト対象。

## やらないこと
- 超過EXPが多いほどLv200時点の攻撃力・HP・装備強化率・光界値を増やす。
- Lv200到達後の獲得数をそのまま「Lv201の必要EXP」の代わりとみなす。
- 次期の新地域・エンドコンテンツの最低Lv条件を現在の超過EXPで判定する。
- 仲間の個別Lv/EXPの追加や、超過EXPを使う新通貨の追加。
- 上限到達後のレベルアップ処理を毎回実行して必要EXPを無制限に計算する。
