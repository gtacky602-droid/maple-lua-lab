## 実装へ接続する順序

1. 設計IDの範囲をレビューする。既存の仮依頼と目的を比較し、置換/拡張/独立を決める。まだ`MANIFEST.json`をランタイムへimportしない。
2. 現行のregion/branch/hidden IDへ、実在するワープ/神像を基礎とするステージを割り当てる。本書の区画名だけで公式座標を作らない。
3. 話者ID、選択中仲間の表示分岐、状態、受取を実装前に定義する。共通状態契約は[COMMON](COMMON.md)。サブの細かな前提は本文を正とし、索引の37本は主要な物語順序のみ。
4. 最初はモンドM01から一周させるが、それだけを全体完成とはしない。残り8地域・9分岐・3隠し・成長/日次の制作範囲を維持。
5. 実際の討伐速度と取得EXP/モラ/装備で、地域進行と光界値育成を校正する。脚本内の戦闘演出を根拠に倍率やCTを勝手に変更しない。
6. 保存、再接続、重複受取、マルチ個別進行を検証する。試作のPASSを幻境のAPI保証へ置き換えない。
7. 制作済みの実数だけcoverage/encountersへ反映。153は設計索引の件数であり、現行ゲームの完成依頼数ではない。

## 再利用する実装要素

新規の複雑なシステムをクエストごとに増やさず、2〜3状態の装置、固定足場、会話フラグ、限定の選択パズル、既存の群れ/精鋭、任意の再戦を共用する。水中、ボード、列車、写真、模型、舞台操作は個別の小さな試作範囲を切り、検証後に拡張する。

仮の新ボス名は設計上の識別子にとどめ、既存の通常/週/幽境リストを削らない。ボス側のHP/体勢/無敵/復活ルールは最新の分野別資料に従う。複数資料に食い違いが残る場合は、本人方針と最新の対象分野資料を優先し、修正箇所を明記する。
