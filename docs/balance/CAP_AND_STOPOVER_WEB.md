# Lv180〜200の狩り場とオシカ・ナタの寄り道

Lv180以降も通常狩りを続けると次の狩り場が順に開きます。各門の条件は表の到達レベルです。オシカ・ナタの依頼は船で寄港したときに進められます。背景はラボで使う仮画像です。本番の背景は3D配置で用意する想定です。

| 通過レベル | 出発地 | 門の座標 x | 到着地 |
| --- | --- | ---: | --- |
| 180 | 湯気谷・鉱泉段丘 | 1790 | 星脈坑・凍てた坑口 |
| 185 | 星脈坑・凍てた坑口 | 1760 | 星脈坑・群青の採掘路 |
| 190 | 星脈坑・群青の採掘路 | 1790 | 暁晶尾根・露頭の道 |
| 195 | 暁晶尾根・露頭の道 | 1790 | 暁晶尾根・稜線の段丘 |
| 200 | 暁晶尾根・稜線の段丘 | 1790 | 極地の暁晶原 |

各マップの通常敵は28体です。Lv200到達後も討伐EXPが累計と上限到達後のEXPに加わり、セーブに残ります。Lv200の敵1体は、既定の条件で296,366 EXPです。

星脈坑の坑口と極地の暁晶原は、初めて到達するとワープ先に登録される。終着駅で荷物を整理したり、保存から再開したりしたあと、ワープ一覧から狩場へ戻れる。 [登録と再訪の検証](../SNEZHNAYA_WAYPOINTS_WEB.md#終盤の狩場への再訪)

## 新規Lv1のセーブでLv200へ

白虹峠を終えたLv160のセーブを使い、極光谷・湯気谷・星脈坑・暁晶尾根を順に通った。Lv160で光界解放中の通常攻撃を当て、Lv170の湯気谷では雷撃を光界反響で写して次の群れに当てた。Lv180の星脈坑では共有ゲージ100を使って七律開天を発動した。ドラゴンスパインの観測と、敵から拾った聖遺物で花・羽を更新する目標を含め、成長依頼5件を報告した。 [Luaの試走ログ](../../evidence/cap-fresh-route.json)

| 通行Lv | 次の狩場 | 検証 |
| --- | --- | --- |
| Lv160〜175 | 極光谷・氷の切通し、氷棚、湯気谷・温泉水路、鉱泉段丘 | 地図と現地の必要Lv、通常の移動、光界解放・反響 |
| Lv180〜200 | 星脈坑・凍てた坑口、群青の採掘路、暁晶尾根・露頭の道、稜線の段丘、極地の暁晶原 | 地図と現地の必要Lv、七律開天、装備更新、Lv200到達 |

Lv160から到達までのLua内経過は18時間35分19秒。狩りは自動戦闘を使用し、荷物整理で28回帰還した。戦闘不能での帰還は0回。上限に達してから暁晶原で1分戦い、71体の討伐で21,041,986 EXPを得た。Lvは200、次のLvへ向けたEXPは0のまま、基礎累計・総累計・上限後EXPに同額が加わった。Chromeでも9区間を歩き、追加討伐と再読込の後に「共通Lv 200 MAX」と各累計が表示された。手動での育成時間は未計測。 [M地図の道順](../../evidence/cap-fresh-atlas.png) · [Chromeの検査ログ](../../evidence/cap-fresh-route-browser.json) · [MAX表示](../../evidence/cap-fresh-exp.png)

同じLv200のセーブから、モンドの入門螺旋3区画を星3で突破し、選んだ黄金の劇団の聖遺物を受け取った。ファルカの通常模擬戦と北風の王狼も倒し、3件の成長依頼を報告。上限後EXPと挑戦記録を保存し、成長Q-G09〜16の完了を同じ冒険データで確認した。 [挑戦の検証ログ](../../evidence/cap-fresh-challenges.json)

`python -X utf8 test_cap_fresh_route.py` はLv160の到着セーブから開始する。`--replay` を付けるとLv1から再生成する。出力は `work/cap-fresh-route/lv200-save.json`。続けて `python -X utf8 test_cap_fresh_challenges.py` で `lv200-challenges-save.json` を出力。ブラウザのLv200検証は `node test_cap_fresh_route.mjs`。

### 同じ比較版の冒険をLv200まで継続

ナタで装備を立て直し、ナド・クライと白虹峠を通った比較版のLv160セーブから、極光谷、湯気谷、星脈坑、暁晶尾根へ進んだ。光界解放、光界反響、七律開天をLv160、170、180の戦闘で使い、装備更新を含む成長依頼5件を報告した。Lv200までのLua内時間は18時間53分45秒。道中の装備を70回更新し、荷物整理で28回帰還した。回復のみの帰還と全滅は0回。狩りには自動戦闘を使用した。 [比較版の試走](../../evidence/cap-fresh-route-draft.json)

Lv200到達後に暁晶原で1分戦うと、56体を倒して16,596,496 EXPが加わった。Lv200・次レベル向けのEXP 0を保ったまま累計と上限後EXPが増え、白虹峠の剣と成長依頼の記録も保存から再開できた。同じLv200のセーブから入門螺旋3区画を星3、ファルカの通常模擬戦と北風の王狼を討伐し、成長依頼を3件追加で報告した。 [上限後の挑戦](../../evidence/cap-fresh-challenges-draft.json)

ChromeでLv200のセーブを読み込み、M地図を開いて終着駅から暁晶原までの9区間を歩いた。到着後の討伐で296,366 EXPを追加し、再読み込み後もLv200、次レベル向けのEXP 0、上限後EXPと累計を確認した。 [道順](../../evidence/cap-fresh-atlas-draft.png) · [Lv200の表示](../../evidence/cap-fresh-exp-draft.png) · [Chromeの記録](../../evidence/cap-fresh-route-browser-draft.json)

比較版の再検査は、白虹峠の比較版から `python test_cap_fresh_route.py --draft-balance`、続いて `python test_cap_fresh_challenges.py --draft-balance`。出力は `work/cap-fresh-route-draft/lv200-save.json` と同フォルダの `lv200-challenges-save.json`。ブラウザーの検査は比較版のラボURLと `DRAFT_BALANCE=1` を指定して `node test_cap_fresh_route.mjs` を実行する。

## 寄港クエスト

ナタの港で乗船し、航海開始から30秒以上50秒未満に甲板の出入口で `F` を押すと、オシカ・ナタに下船できます。寄港地では時間を気にせず探索できます。波止場の左端で再乗船すると、残り40秒でナド・クライへ到着します。下船せずに乗り続ける場合は、出航から90秒で到着します。その後、ナタへ帰る船でも寄港できるようにしました。寄港地で再乗船してから保存した場合は、同じ寄港地から再開します。 [南行きの航海と試走](../SITES_RETURN_FERRIES_WEB.md)

| 依頼 | 受注レベル | 進め方 | 初回報告（EXP / モラ） |
| --- | ---: | --- | ---: |
| 途中下船も、冒険のうち | 180 | 潮待ちの石段で3か所の印と道筋を順に調べる | 11,200,000 / 5,100 |
| 岩の隙間に、置いてきた印 | 182 | 継ぎ壁の中庭で刻み目を調べ、通路を塞ぐ運搬機を倒して奥の印を調べる | 15,500,000 / 6,800 |
| 出航前の、もうひと仕事 | 185 | 焚き口の選鉱室で礫脈の選鉱炉を止め、奥で寸法を測る | 8,653,565 / 797,220 |

各依頼は寄港地で受注・報告します。次の依頼は前の報告後に受注できます。初回報酬は報告時に一度だけ入ります。選鉱炉の討伐では通常の討伐報酬が入ります。報酬と敵の数値は調整用の試作値です。

## 礫脈の選鉱炉

「左右の踏み割り」は地面の左右2か所を同時に攻撃します。中央に安全地帯があります。「三本の排熱流」は攻撃開始時に位置が決まり、予告した3列を順に攻撃します。1回の攻撃中に同じ味方が受けるダメージは1回までです。攻撃中は装甲が有効で、攻撃後の冷却中に回転輪を狙うとダメージが1.3倍になります。光界35は手動比較用の目安です。

共闘は寄港地や石段で部屋を作り、選鉱室で合流できます。装甲と冷却中に露出する回転輪を共有し、寸法の記録と報告は各自で進めます。 [共闘の入口と検証](../COOP_WEB_PREVIEW.md#霜鎧の大角獣と礫脈の選鉱炉)

## 検証

Lv180の検証用セーブから、既定の2人編成、自動戦闘、装備変更なし、寄港依頼なしでLv200に到達しました。42,595体を討伐し、戦闘の経過時間は51,950.78秒（約14時間26分）でした。荷物の回収と売却は4回、パーティー回復は11回です。移動と荷物整理の操作時間は計測外です。Lv200到達後は極地の暁晶原で60体を倒し、累計に17,781,960 EXPが加わった状態で保存と再開を確認しました。 [成長ルートの検証記録](../../evidence/endgame-180-200.json)

Chromeで同じ冷却中のフレームを比較したところ、画面全体の描画命令は標準矩形14,332件、軽量16色3,600件でした。軽量16色では細かな質感が簡略化され、外形と露出した青緑の回転輪は見分けられます。 [PNG表示](../../evidence/stopover-boss-png.png) · [軽量16色](../../evidence/stopover-boss-light.png) · [Chromeの検証記録](../../evidence/cap-stopover-browser.json)

```text
python test_endgame_160_180.py --to-cap
python test_cap_stopover.py
node test_cap_stopover.mjs
```

Chromeの検査は、ポート8858でラボを起動し、`test_cap_stopover.py` で検証用セーブを生成してから実行します。
