## 2. 再現コマンド

リポジトリのルートから実行する。

```bash
python docs/field-boss-v1/validate_nod_krai_quartet.py --self-test --check-runtime-source
python -O docs/field-boss-v1/validate_nod_krai_quartet.py --self-test --check-runtime-source
python -m py_compile docs/field-boss-v1/validate_nod_krai_quartet.py
```

`--check-runtime-source`は旧試作との比較専用。FBT03は旧`moves`配列の外の`coolingMove`にあるため、両方を集計する。ランタイムが新仕様へ移行した後は、旧試作値との一致を要求するこのオプションを外して通常の宣言検査を使う。

## 4. 移行時に読み飛ばさない点

| 項目 | 必須の扱い |
|---|---|
| 盾値0とダウン | 旧`duckWard/iceWard/damageShield<=0`の自動ダウンhookを撤去する。初期値0にするだけでは即ダウンする |
| 3つの攻撃履歴 | 旧`seen`2枠を前提にしない。FWN03は漁手1・漁手2・本体放出の3groupを生成する |
| 子の座標 | 全矩形はボスのLOCK原点基準。ownerが子でも子の位置を再加算しない |
| 死亡と期限 | 有効死亡の最終受付は299tick。300tickの退場、到達、cleanupを破壊成功へ数えない |
| 世代 | epoch＋encounter＋parentCast＋slotで識別。旧負IDの再利用で過去のDoT・通知を新しい子へ渡さない |
| 同tick | プレイヤーダメージ適用→本体HP0→子死亡／板→中断→期限退場→敵攻撃。HP0なら以後は終了 |
| 板の時刻・接触 | 遭遇の共通時計から親cast基準へ変換する。板の実領域と新しい直接castを照合し、本体onHitだけで削らない |
| 二重適用 | 板を別HP receiverにしない。本体のHP・付着・on-hitを重複処理しない。実体の子から本体へHP転送しない |
| 古い選択器 | 炎4castによるFBT03即差替えと、漁手の独立周期攻撃を残さない |
| 地形端 | 個別clampやLOCK直後反転を外す。成立する地上経路がなければ非攻撃再配置と新しい予告へ戻る |

ダックの2機は異なる位置に出現するが同じ到達位置へ近づく。**移動中のhurtbox非重複を保証する設計ではない。** 非重複にする対象は漁手2つと本体放出の攻撃窓であり、子は実壁にしない。実体同士の重なりには通常の各receiverの命中処理を使い、本体へ複写しない。

旧ダックの到達効果は盾値＋25で、本体HPの回復ではなかった。今回「HP回復なし」は新設計の保証であり、旧コードにHP回復があったという説明にしない。

## 5. 新ランタイム接続後の検査

- **物理のみ・ギミック無視：** 4体を本体への通常攻撃で撃破できる。召喚、冷却、薄闇がHPロックや隠れた追加軽減を作らない。強い装備で看板前に倒せる。
- **空中・潜行：** ダック／霊主の絵とhurtboxが36tickの軌道に一致する。魘夢は36tick潜行の後24tick見え、地面マーカーにHPを持たせない。潜行中のDoT撃破で再出現や報酬が重複しない。
- **任意中断：** 窓の開始直前／開始／299／300tickを確認。直接攻撃・反応・DoTで同じ子が同tickに死んでも1件。親撃破と子撃破が同tickなら親の終了が優先する。
- **召喚：** 1体だけ倒したケース、既に攻撃した漁手を倒したケース、時間切れ、撤退、再入場を確認。中断は一度だけで、未来の攻撃・自然REC・旧世代の予約が残らない。子に経験値・クエスト進行を付けない。
- **冷却板：** 露出前の弾、DoT、反応、多段通知で層が誤減少しない。物理1・炎2、活動中の同行、板だけの命中、本体だけの命中、同時命中を分ける。
- **地上退避と復帰：** 左右端、段差、近接・遠隔、低い移動速度、複数人で確認。本体や子を通り抜けない経路と、看板後に戻って殴れる時間を測る。
- **調整：** 適正Lv・標準装備の45〜90秒を測る。HP16×2の補修メカ、HP60×2の漁手は現行比較値。漁手の受付3.8秒内で最小構成が中断できるかは別途測定し、未達を本体無敵化で補わない。
- **演出と実機：** 突進の固定刃帯、子攻撃の範囲、薄闇の輪郭、板の亀裂と実判定、音、Webマルチ、幻境移植を別々に記録する。

本書の静的PASSはこれらの実機項目の合格を代用しない。
