# フィールドボス共通：短い遭遇・読みやすい一手 v0.1

2026-11-17。本人指定はママシュ程度の立ち位置。[MASTER](../../DESIGN_FIELD_BOSS_MASTER_V01.md)と併読。数値は制作開始案。Web実装は最新の全体指示に従ってよいが、今回の差分は設計でありランタイムを変更しない。

## 1. 一戦の構造と負荷

`AVAILABLE → NOTICE → COMBAT → DEFEATED → RESPAWN_WAIT → AVAILABLE`。
撤退時は`COMBAT → LEASH_RETURN → AVAILABLE`。HP0勝利は未発動技・撤退・リセットより優先。HP0を止めて看板技を必ず見せることはしない。

初回攻撃または近い警戒範囲でNOTICE。24〜48tickの非攻撃の振り向きから通常のTELLへ入る。プレイヤーの入力を奪う入場演出なし。道からの見物・通過だけで画面外から全域攻撃しない。入口から見える輪郭・寝息・葉の揺れを発見の演出に使う。

標準3技、1cast同時。通常2〜3回の間に看板1回、同じ看板の連発なし。技間に24〜48tickの歩行／呼吸を置く比較案。全ての攻撃に常時スーパーアーマーという新設定を加えず、既存ノックバック／拘束耐性との接続は実装時に比較する。低HPで速くする場合も位置固定後の猶予を削らず、既存技の選択頻度だけを調整する。

既存の狩場12〜20体/画面を全体で減らさない。ただしボスの小広場はボス1体と自然に残る普通モブ0〜3体程度を比較し、ボス戦のために増援を無限生成しない。ボス自身の召喚を採用する後続個体でも同時2体程度、一つの短い波から始める。景観の広さとソロ経路を先に確保する。

## 2. HP、攻撃機会と難度

適正Lvの旅人＋同行1人・標準装備で45〜90秒が目標。HP初期候補は、同Lvで測った有効DPSと実際に攻撃できる割合から逆算する。HP=通常敵の何倍という値だけで、45秒になると断言しない。今回HP/攻撃力を変更しない。

- 原則戦闘中の本体にHPダメージが通る。盾や核は『早く倒すための有利』へ寄せる。
- 無敵の形態移行、別HPへの全回復、瀕死の復活試験、長い回収ノルマは普通フィールド版の初期構成に含めない。
- 特定元素の既存耐性・無効は既存データと原作方針を照合して扱う。視覚が同色というだけで勝手に完全無効へしない。物理通常で最後まで戦える経路を保持する。
- HPが十分減れば看板前に倒せてよい。成長したら短く倒せることを価値にする。Lv上限200と地域の既存Lvを変更せず、訪問者の最大Lvへ自動調整しない。
- 難度選択は本カテゴリの初版へ追加しない。後の強化個体は地方伝説・別挑戦として名前／ID／報酬を分ける検討事項で、同じ敵へ暗黙に上乗せしない。
- 週ボス・幽境の専用復活、命ゲージ、確定死、反射即死は転用しない。

## 3. 接触と攻撃は別に予告する

大きい敵に近づきすぎる怖さは残すが、見た目全体を危険にしない。

BODY_CONTACTは地上の胴・根元の小さい領域にだけ設定する候補。髪、葉先、飾り立方体、尾の余韻、飛翔エフェクトには追加しない。挟み技等で本体と同時に重なっても、同tickの一対象には技か接触の片方だけを要求する。既存の被弾無敵0.6秒等を短縮・延長して接触処理の帳尻を合わせない。

接触再要求は同actorにつき60tick以上を初期上限とし、毎フレームの押し戻しや永続ノックバックは付けない。ノックバックの採用は別設定。ダウン中、帰還中、死亡後、再出現猶予中はBODY_CONTACTを止める。待機中に少し触れただけの即死はない。接触の威力は既存被ダメ表から決め、看板の一撃より重くしない候補。

FIELD_STARTER4では、本体が実壁になって背後へ行けない場合も、正面から横へ離れる／跳ぶ経路を残す。『体をすり抜けられるはず』を唯一の安全策にしない。攻撃中にボスが方向を反転する場合は新しい予兆が必要。

## 4. 表示・音・タイミング

60tick/秒、区間[start,end)、U=88px、x右/z上。画面は960×540を比較用とする。普通の小広場は幅8〜10Uの地上床、上段は任意。必須対処を上段到達や特定仲間の浮遊に依存させない。

各技はTELL→LOCK→ACTIVE→RECOVERY。一つのため姿勢、局所的な床線か影、攻撃、息継ぎで分かるようにする。通常予兆は0.7〜1.0秒程度、看板は1.2〜1.8秒程度から比較。実際の脅威と逃走距離で決め、速さの数字だけを優先しない。

本人・手足・部位の予備動作を主情報とする。最初から床へ巨大な幾何図形を5枚並べない。敵種の色と別の濃い輪郭／細い明色縁で危険な部分を示す。開始時の終点ロック後に無限追尾しない。

本体は普通モブより大きく、2D素材の非人型へ人型頭身を強要しない。炎や氷の厚い面で自機を隠さず、看板の実命中だけ共通Hit Coreを強める。空振りに架空の数字を出さない。通常被弾は小さな点滅・局所火花、画面揺れは既定0、任意でも重い接地に最大1px/6tick。reduced_motionは0。音なしで読み取れる。

共通素材群：待機2、歩行／揺れ2〜4、攻撃各4〜6キー姿勢、短い硬直／任意ダウン2、撃破2を比較基準とする。基準20〜28姿勢程度は素材見積もりであり制作済み枚数ではない。同じ攻撃を上下移動させるだけで違う技にしない。色替えの派生は骨格・タイミングを再利用してよいが、花の弾とキューブの掌などの識別形状を失わない。

## 5. 一つの特徴を、短いルールにする

急凍樹では核を壊すと短く倒れる。核を処理しなくてもHP0で倒せる。
無相は立方体の組み替えと攻撃後の露出を残し、通常フィールド版では露出以外でも低い核のHP領域へ当てられる翻案。
マッシュラプトルは大きい跳びかかり後によろける。活性ゲージ・枯渇・雑魚召喚を全て覚える必要はない。

これらは原神全挙動の完全再現ではない。週ボスにある原作攻略再現の密度と、フィールドの短時間・周回の密度を意図的に分ける。以後のフィールド個体も1文の個性が決まるまで第四技を追加しない。

## 6. 出現・撤退・再挑戦

初期案では地域マップ内の既存ボス出現枠を使う。初回のそのセッションにはAVAILABLEで置く。討伐後は60秒で再出現する比較値。常設の世界共有2時間湧き・樹脂・週回数・サーバー間の取り合いは導入しない。時間待ちがある場合、あと何秒かを近くで確認できるようにし、待つ間は周辺を狩れる。

出現枠は `(worldOrPartyInstanceId, spawnSlotId, respawnGeneration)` で保持。マップのロード／アンロードや同じセッションへの再接続で新規個体と報酬を毎回作り直さない。再出現時刻の進み方は実装のワールド時計を使用し、ソロ一時停止と整合させる。壁時計とゲーム時計を混ぜない。別セッションを新設した場合の引継ぎはホストの保存方針と相談して別決定。恒久的な世界共有資源を勝手に足さない。

撤退は警戒範囲の外へ出る。すべての有効標的が5秒以上外にいる場合を帰還開始の候補にし、他の参加者が戦っているとき一人の逃走で全回復させない。帰還は非攻撃・報酬なし。帰還開始で旧弾を消し、家へ戻ってからHPリセットを表示する。帰還中の攻撃は受け付けず、ダメージと回復が交互に無限発生しない。リセットを成功した討伐と数えない。

全滅後は既存の復帰地点から再挑戦。ロノヴァの灯を追加せず、この設計だけで既存の死亡ペナルティや復帰APIを変更しない。HP0と撤退が同tickなら撃破・一度の報酬を先に確定する。

## 7. 報酬・周回・マルチ

敵Lv／HPの強さと報酬倍率は別。現行の敵EXP案はフィールド50倍、週150倍などだが、週ボスには別の周回予算案もある。今回の短い戦闘へ、その豪華な週ボス報酬をコピーしない。元の指定セット／装備抽選は保持し、フィールド専用の新通貨や必須の新技を作らない。

周回効率の分母は実戦＋移動＋湧き待ち＋結果時間。60秒撃破だから50倍EXPを毎分50倍得られるとは限らない。強くなって短く倒す利益は残し、低Lvの一体だけで全育成を終える強制スケールや報酬指数にはしない。報酬率の再計算は別のバランス差分として記録する。

人数でボスHPを増加しない本人方針を維持。報酬は既存の参加資格を満たす個人へ一度。最後の一撃だけを報酬条件にして横取りを促さないが、見物・同じマップにいるだけで無条件配布も決定しない。貢献定義は既存の攻撃/支援集計を再利用し、欠けているなら未接続として扱う。

一つの出現世代の `(spawnGeneration, encounterId, realPlayerId, rewardVersion)` に対して一度だけ報酬確定。再出現時に新世代、同一死亡通知の重複やcleanupは無報酬。章ボス初回・依頼報酬の既存フラグと統合し、同じ達成で『フィールド初回＋章初回』を無断に重ねない。

## 8. 受け入れ条件

実装者は、単独物理通常→同行不在/倒れている→通常の同行→複数実プレイヤー、の順で試す。『通常で突破可』は手数・射程・期限の実測が必要。今回は長い必須試練を取り除いて、その種類の進行不能を減らす。

必須確認は、接触と技の重複、地上の近接Hurtbox、実表示と予兆、初回に覚えられる3技、HP0優先、背後すり抜け不要の退避、地域の狩りを邪魔しない配置、他人の逃走によるリセット、途中参加の資格、同一世代の重複報酬、再接続での湧き直し。

テキストのタイミング検査と実ゲームの回避検査は別。美術参照と現行実装を確認し、旧無相の完全無敵などとの変更箇所を残してから接続する。未変更のゲームコードを修正済みと呼ばない。
