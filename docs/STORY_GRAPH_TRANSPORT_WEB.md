# 地図・依頼データの通信を軽量化

[軽量版のローカルラボ](http://127.0.0.1:8974/)を開き、「本編ルートへ」を選ぶ。従来どおりMキーで地図が開く。[ドット絵の比較画面](http://127.0.0.1:8974/compare.html)でも同じ通信方式を使う。既存のローカルセッションを保つため、今回のサーバーは8974で起動した。別ポートのセーブは従来のファイル書き出し・読み込みで引き継げる。

Luaは、表示できる地点・経路・依頼の定義を保持する。ブラウザは初回に受け取った定義を再利用する。新しい地域を発見し、初回訪問が条件の門や依頼の進行で隠れていた入口が現れたら、更新後の定義を受け取る。HP、位置、描画命令、依頼の進み具合は通常のフレームで更新する。再読み込み・セーブ復元・初期化でも、そのセッションに合う定義を受け取る。従来形式でフレームを要求するツールにも全項目を返す。

## 同じ場面での比較

同じラボ・同じセッション内で、従来の全項目つき応答と軽量応答を交互に各12回取得した。表は中央値。ゲーム時刻を止め、Luaの描画命令も照合した。単位は1 KB = 1,000バイト。 [HTTP計測](../evidence/story-graph-transport.json)

| 場面 | 従来形式 | 軽量形式 | 転送量削減 | HTTP応答 |
| --- | ---: | ---: | ---: | --- |
| モンドの開始地点 | 1,206 KB | 12.0 KB | 99.01% | 59.38 → 2.61 ms |
| 金リンゴ群島の狩場・敵48体（画面内16体） | 1,221 KB | 9.1 KB | 99.25% | 73.30 → 2.89 ms |

両場面とも描画命令とゲーム状態は一致した。初回や新しい経路を発見した直後は定義全体を受け取る。応答時間はこのPCでのローカル測定。星々の幻境の描画速度・通信性能は未計測。

## 検証

- HTTPで隠し世界の発見、初回訪問、依頼で現れる門と地点、旧セーブの依頼記録、更新応答の取り直し、再読み込み、初期化、保存復元を確認した。 [検証ログ](../evidence/story-graph-transport.json)
- ChromeでMキーの地図を開き、実際に金リンゴ群島の手がかりを調べて地図が更新されることを確認した。再読み込みで同じ冒険が続き、ドット絵の比較画面も軽量応答の途中で描画を続けた。 [Chromeログ](../evidence/story-graph-browser.json)

再計測は `python -X utf8 test_story_graph_transport.py`。ブラウザ検証は8974でサーバーを起動し、`node test_story_graph_transport.mjs`。
